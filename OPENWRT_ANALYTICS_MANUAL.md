# OpenWrt Network Analytics Platform

## Operations, configuration, and reinstallation manual

This project provides traffic-volume analytics without DPI, SNI, destination
hostname, DNS-query, application, or service collection.

## What is collected

- Per-device download/upload counters by address family, MAC, and IP.
- Friendly device names, inventory, first/last seen, and online state.
- Forwarded download/upload totals for each configured WAN.
- WAN status, interface rates, router health, and collector health.
- Prometheus minute, hourly, and daily rollups for retained metrics.

`nlbwmon` rows are aggregated before export. Transport protocol, port, and
Layer-7 fields are intentionally discarded to reduce router, network, and
Prometheus overhead.

## Components

OpenWrt runs `nlbwmon`, passive nftables WAN counters, mwan3 collectors, device
inventory/name helpers, and `prometheus-node-exporter-lua`. The analytics VM
runs Prometheus, node exporter, and Grafana.

The nftables chain is attached to the `forward` hook, so its WAN totals cover
LAN-to-WAN/WAN-to-LAN forwarding and exclude traffic generated by the router
itself. Interface counters are retained as an independent rate reference.

## Configuration

Copy `config.example` to the ignored `config.env` and set:

- router/server addresses, SSH users, and ports;
- the LAN CIDR used by nlbwmon;
- one to three positional `WAN_NAMES` and `WAN_DEVICES` entries;
- optional local domain and DNS servers for device-name PTR discovery;
- Prometheus time and size retention limits.

Do not store passwords or private keys in either file.

## Install or upgrade

Run from Linux, macOS, WSL, or Git Bash with Python 3, SSH, and SCP:

```sh
cp config.example config.env
$EDITOR config.env
./manage.sh check
./manage.sh render
./manage.sh test
./manage.sh install
./manage.sh status
```

`install` performs router deployment first and server deployment second.
Re-running it is the supported upgrade path. Existing managed configuration is
backed up before replacement. Router firewall configuration is checked with
`fw4 check` before reload; Prometheus configuration and rules are checked with
`promtool` before restart.

Use `install-router` or `install-server` to deploy one side only.

Upgrades from the former classification build stop and remove Netify and its
stream/guard helpers, remove application collectors and nftables rules, retire
the two application/service dashboards, and install the totals-only WAN
collector. Historical retired Prometheus series are left in the TSDB and age
out under the configured retention policy.

## Dashboards

- **OpenWrt Firewall Analytics** — health, WAN totals/rates, top devices, and
  selected-device usage.
- **OpenWrt Device Analytics** — identity, IP history, selected-range totals,
  bandwidth, first/last seen, online state, and behavior trends.
- **OpenWrt WAN Analytics** — status, online time, selected-range totals, and
  bandwidth for each WAN, plus separate 07:00–24:00 and 00:00–07:00 local-time
  download/upload totals.
- **OpenWrt Long-Term Analytics** — minute peaks plus hourly/daily device usage.
- **OpenWrt Device Inventory** — device names, addresses, presence, and history.
- **OpenWrt Data Quality** — scrape health, collector reconciliation, resets,
  duration, and series cardinality.

All bandwidth panels use Grafana's SI bitrate unit so values automatically
display as bps, kbps, Mbps, or Gbps. Usage panels display bytes with automatic
scaling.

## Device names

Names are discovered from OpenWrt host hints, DHCP leases, and optional PTR
queries. Manual MAC aliases take precedence:

```sh
device-name set 02:00:00:00:00:01 "Living Room TV"
device-name list
device-name remove 02:00:00:00:00:01
```

These are local device identity names. Destination hostnames and DNS queries
are not retained.

## Operations and backup

```sh
./manage.sh status
./manage.sh backup
```

The backup command downloads managed configuration and the Grafana database;
it does not copy the Prometheus TSDB. Use a stopped-service filesystem or VM
snapshot for a consistent TSDB backup.

After an OpenWrt firmware upgrade, confirm package feeds, rerun
`./manage.sh install-router`, and then run `./manage.sh status`. After changing
WAN interfaces, update both positional lists in `config.env` and rerun the
router and server installers.

## Validation

Check that:

1. `nlbwmon` and `prometheus-node-exporter-lua` are running on OpenWrt.
2. `fw4 check` succeeds and `prometheus_wan_totals` exists.
3. No `netifyd`, Netify stream, or Netify guard process/service remains.
4. Prometheus reports all configured targets up and no Netify scrape job.
5. `openwrt_wan_bytes_total` and aggregated `nlbwmon_*` series update.
6. Grafana provisions six dashboards and no application/service dashboard.
7. Internet access, mwan3 policy routing, DNS/DHCP, and configured VPNs remain
   healthy.

## Troubleshooting

If a dashboard is empty, check Prometheus targets, query the metric directly,
and confirm that the selected Grafana time range contains traffic. If WAN
totals are missing, compare configured WAN device names with `ip link`, inspect
the nftables chain, and rerun the rendered installer after correcting the map.

Short speed tests may be smoothed by rate windows. Use the live dashboard with
a short time range for burst inspection; long-term panels intentionally show
rollups.

Collector totals need not be identical: interfaces include their own scope,
nftables measures forwarded WAN packets, and nlbwmon measures LAN-device
accounting. The Data Quality dashboard makes these boundaries visible.

## Privacy and limitations

MAC randomization and DHCP changes can create new identities. Manual MAC names
help maintain continuity. Router restarts reset volatile nftables counters;
Prometheus handles counter resets, but a restart boundary can reduce an
`increase()` result for that interval.

Keep the exporter, Prometheus, and Grafana on a trusted management network. Do
not port-forward them to the Internet; use a VPN or authenticated TLS reverse
proxy for remote access.
